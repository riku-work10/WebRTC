# 04 学習記録: 引用符とグロブ

[demo.sh](demo.sh)を実行して確認した。

## クォートの違い

```
'$NAME'  → single quote: $NAME     (シングルクォート内は一切展開しない、完全な生文字列)
"$NAME"  → double quote: world     (ダブルクォート内は変数展開・コマンド置換だけ有効)
$NAME    → no quote: world         (クォート無しは展開した上でさらに単語分割・グロブ展開の対象になる)
```

## コマンド置換

```
`echo nested`   → nested
$(echo nested)  → nested
```

結果は同じだが、`` `...` ``はネスト(入れ子)しにくく、エスケープが複雑になりやすいため、現代では`$(...)`が推奨される。

## グロブ(ワイルドカード)

`a.txt`, `b.txt`, `c.log`を作った上で確認:

```
*.txt   → a.txt b.txt         (任意の0文字以上に一致。c.logは対象外)
?.txt   → a.txt b.txt         (任意の1文字に一致。今回はどちらも1文字なので同じ結果)
[ab].txt → a.txt b.txt        (角括弧内のいずれか1文字に一致)
```

グロブはシェル自身が展開してから外部コマンド(この場合`echo`)に渡している。つまり`echo *.txt`は`echo`が`*.txt`という文字列を受け取っているのではなく、シェルが先に`a.txt b.txt`に展開してから`echo`に渡している(`echo`はグロブの仕組みを一切知らない)。

## クォート無し変数展開と単語分割

```bash
MULTI="one two three"
set -- $MULTI      # クォート無し → 単語分割されて3つの引数になる → count=3
set -- "$MULTI"    # ダブルクォート → 1つの文字列のまま → count(quoted)=1
```

変数展開後の文字列は、クォートしないとスペース区切りで複数の単語(引数)に分割されてしまう。これはPhase3のPythonソケットスクリプトの引数処理(`sys.argv`)とは異なり、シェル特有の落とし穴。ファイル名にスペースが含まれる場合などにバグの原因になりやすいため、変数展開は基本的に`"$VAR"`のようにダブルクォートで囲む習慣が推奨される。
