# 03 学習記録: シェル変数と環境変数

[demo.sh](demo.sh)を実行して確認した。

## シェル変数 と 環境変数の違い

```bash
FOO=bar                     # シェル変数: 今のシェルプロセスの中だけで有効
bash -c 'echo $FOO'         # → 空。子プロセス(bash -c で起動する別プロセス)には見えない

export FOO                  # 環境変数に昇格: 以後起動する子プロセスに自動で引き継がれる
bash -c 'echo $FOO'         # → bar
```

実行結果:

```
1) 通常の変数は今のシェルの中でしか見えない: bar
2) 子プロセス(bash -c)からは見えないはず:
   subshell: FOO=[]
3) export した後は、子プロセスにも環境変数として引き継がれる:
   subshell: FOO=[bar]
```

`export`は「これ以降に起動する子プロセスへ渡すコピーに含める」という指示であって、親から子への一方通行。子プロセス側で環境変数を変更しても、親のシェルには影響しない(プロセスごとにメモリ上の環境変数表が別々にコピーされるため)。

## `env` と `set`

```
env の行数: 65   → export済みの環境変数だけの一覧
set の行数: 88   → シェル変数・シェルオプション・関数定義まで含む、そのシェルの全状態
```

`env`は「子プロセスに渡るものだけ」、`set`は「今のシェルが知っている全部」という関係。

## 設定ファイルの読み込みタイミング

```
~/.zshenv   → 常に読まれる(ログイン/非ログイン、対話/非対話 問わず全部)。今回のマシンには存在しなかった
~/.zprofile → ログインシェルの時だけ読まれる(macOSではターミナルを開くたびにログインシェル扱いになることが多い)
~/.zshrc    → 対話シェル(interactive)の時だけ読まれる。alias, PATH追加などは大抵ここに書く
```

01で調べた「ログインシェル/インタラクティブシェル」の区分と対応している。`echo $PATH`が複数箇所で重複していた([01](../01-shell-basics/NOTES.md)のPATH一覧を参照)のは、`.zprofile`と`.zshrc`など複数ファイルで同じディレクトリをPATHに追加しているためだと推測できる。
