# 02 学習記録: パイプ・リダイレクト

[demo.sh](demo.sh)を実際に実行して確認した。

## パイプ `|`

```
cat fruits.txt | grep an
```

左のコマンドの「標準出力」を、右のコマンドの「標準入力」にそのまま繋ぐ。ファイルを経由せず、OSのカーネル内のバッファ(パイプ)でプロセス間を直接繋いでいる。

## リダイレクト `>` と `>>`

```
echo "line1" > out.txt   # 上書き(ファイルが無ければ新規作成、あれば中身を空にしてから書く)
echo "line2" >> out.txt  # 追記(末尾に足す)
echo "line3" > out.txt   # 再び > すると line1/line2 は消え、line3 だけが残る
```

`>`は毎回ファイルを作り直す(トランケートする)動作である点を実験で確認した。

## ファイルディスクリプタ(1=標準出力, 2=標準エラー出力)

```
ls fruits.txt nope.txt 2> err.txt 1> ok.txt
```

`ls`は「見つかったファイル名」を標準出力(1)に、「エラーメッセージ」を標準エラー出力(2)に、別々の経路で出している。これを別ファイルに分けて初めて、`ok.txt`には`fruits.txt`だけ、`err.txt`には`No such file or directory`だけが入ることを確認できた。

```
ls fruits.txt nope.txt > combined.txt 2>&1
```

`2>&1`は「fd2(標準エラー)の向き先を、今のfd1(標準出力)の向き先と同じにする」という意味。書く順番が重要で、`2>&1 > combined.txt`のように先に`2>&1`を書くと、まだ標準出力がターミナルを向いている時点でコピーされてしまい、意図通りにならない(今回は未検証、次回試す)。

## ヒアドキュメント `<<EOF ... EOF`

```
cat <<EOF
hello $(whoami)
EOF
```

複数行の文字列をコマンドの標準入力として渡す構文。`$(...)`のようなコマンド置換や変数展開は、クォートなしの`<<EOF`では通常通り展開される(`hello riku`と表示された)。
