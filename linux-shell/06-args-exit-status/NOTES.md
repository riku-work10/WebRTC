# 06 学習記録: 引数と終了ステータス

[args_demo.sh](args_demo.sh)を`./args_demo.sh hello "world wide"`で実行して確認した。

## 引数を受け取る特殊変数

```
$0   → スクリプト自身のパス(./args_demo.sh)
$1, $2, ...  → 1番目、2番目の引数
$#   → 引数の個数
$@   → 全引数(個々の引数として展開される。"$@"のように書くと元の区切りを保つ)
```

実行結果:

```
arg count ($#):   2
all args ($@):    hello world wide
1st arg ($1):     hello
2nd arg ($2):     world wide      ← "world wide"はダブルクォートで囲んだので1つの引数として渡った
  loop: [hello]
  loop: [world wide]              ← "$@"でループすると2引数のまま(スペースで割れない)
```

`04`(クォート)で学んだ「クォート無し変数はスペースで分割される」問題は、`"$@"`と書くことで回避できる。もし`$@`(クォート無し)でループすると`world`と`wide`が別要素に割れてしまう(未検証、次回確認)。

## 終了ステータス `$?` / `exit`

```
exit 0   → 正常終了
exit 1   → 異常終了(慣習上、失敗を表す。値に決まりは無いが0以外はすべて「失敗」扱い)
```

実行結果:

```
exit code after success: 0
exit code after failure: 1
exit code for command not found: 127   ← シェル自身が「そんなコマンドは無い」と判定した場合の慣習的なコード
```

`$?`は直前に実行したコマンドの終了ステータスを保持する特殊変数で、次に何かコマンドを実行すると上書きされる(確認のためすぐ`echo`する必要がある)。`if`文で`[ "$1" = "fail" ]`のように文字列比較しているのは、Pythonの`sys.argv`と違って引数は常に文字列として渡ってくるため([07](../07-conditionals/NOTES.md)で条件分岐の詳細を扱う)。
