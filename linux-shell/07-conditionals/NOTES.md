## `if` の正体は「コマンドの終了ステータス」

```bash
if [ "$NUM" -gt 3 ]; then ...
```

`if`は「式」を評価しているのではなく、「コマンドを実行して、その終了ステータス($?)が0(成功)かどうか」を見ているだけ。`[`は実は`test`と同じ働きをする**コマンド**であり(`]`はその最後の引数という扱い)、`06`で見た`$?`の仕組みがそのまま使われている。

```
test 1 -eq 1 -> exit=0   (真)
test 1 -eq 2 -> exit=1   (偽)
```

これを裏付けるように、`test`コマンド単体を実行しても同じ結果になった。

## `[ ]` と `[[ ]]` の違い

```
[ ]    → POSIX標準のtestコマンド。全シェル共通で使える。単語分割やグロブ展開の対象になるため変数は必ずダブルクォートで囲む必要がある(例: [ "$NUM" -gt 3 ]で"$NUM"のクォートを外すと、値が空の時にエラーになる)
[[ ]]  → bash/zshの拡張構文。&&/||が直接使える、==でパターンマッチができる、変数展開時に単語分割/グロブが起きないため安全
```

実行結果:

```
[[ $NUM -gt 3 && $NUM -lt 10 ]]   → true (5は3より大きく10より小さい)
[[ $NAME == *.txt ]]              → true (グロブパターンとして比較。[ ]では文字通りの文字列比較になり一致しない)
```

## よく使うファイル・文字列テスト

```
-f FILE   → 通常ファイルとして存在するか
-x FILE   → 実行権限があるか
-z STR    → 文字列が空か(-nは非空)
```

`05`で確認した「実行権限がないと`./script.sh`が失敗する」問題は、事前に`-x`でチェックしてから実行する、といった形で活用できそうだと分かった。
